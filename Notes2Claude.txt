
Twenty years ago, I built a multi tenant website that served over 50 hospital networks - The application focused  on compliance with HIPPA regulations. It was very successful and continues to this day.  Many of the customers requested additional custom applications but we were unable to serve them because the menu system was a shared resource and could not be modified from one customer. I believe that a business opportunity currently exists for two reason:

The custom application were mostly simple and could be quickly and effectively built with Cluade Code

I have designed a unique data driven menu system that offers maximum flexibility for supporting custom application. 

My design concept is to have a single table (fomMenu.dbf) that uses a recursive call to build an unordered list- (function fomMenu() in minimumsupport.prg  line 353) -  The unordered list is displayed as a drop down menu on FOM.HTM  - The same unordered list creates a treeview which is displayed on MENUBILDER.HTML - The treeview enables modifying the sort order and updating the fommenu.dbf


When a menu item is clicked, it sends a message to the server: FOM.CTX?FOMMenuID=(ID)   - The fomMenu.dbf not only builds the menu,  when FOM.CTX is hit, it directs the response (Function menuFunction(tcID) in minimunsupport.prg  then routed to Function widgetHTML(oWidget,tlFOMMenu)) -  For example when ID = 11  (called from Menu->Developer->Add a Menu), the fomMenu.chref = "PrimeMenus.htm"  - that looks for a file with that name in the root folder and returns it.  (Eventually, this function should move to fomPages in PostgresSQL) - When a text file like the one below is uploaded:

The response is directed to (Function PrimeMenus() in menubuilder.prg) and the new menu items are added. It is a main feature of my menu system that the menu can be so easily extended and enhanced via the treeview control

The TreeView has the following capabilities:

Change sort order via drag
Change node stucture via drop
Fetch an edit screen via click on link

Drag and drop send an ajax message to (Function postData() in treeviewbuilder.prg line 184) which enables updating fomMenu with these parameters:

	lnVars = Request.aFormVars(@laVars)
	lcChildID= Request.Form('child')
	lcparentpk= Request.Form('parent')
	lcPrevID= Request.Form('previous')
	lcNextID= Request.Form('next')

	liDraggedID= Val(Substr(lcChildID,3))
	liTargetID= Val(Substr(lcparentpk,3))
	liPrevID= Val(Substr(lcPrevID,3))

Clicking on an element fetches a FORM via ajax (FUNCTION treeViewEdit() in treeviewbuilder)  which is used to update fomMenu - Two forms are used:  one for parent and another for a leaf. The FORMs are returned from Function treeViewForm() and treeviewformshor() in treeviewbuilder.prg  In addition to submitting updates to the server, the forms also modify the TREEVIEW without refreshing the unordered list from the backedn - These include:

Change the class of the text in the list (<a href="#"><span class="black">Hello World</span></a>
Delete a link
Add a sibling
